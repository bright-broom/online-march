# DECISIONS — オーナーの決定と、まだ決まっていないこと

**このファイルは「何を・なぜそう決めたか」の記録。** 会話の履歴や GitHub にアクセスできない AI・人でも、ここを読めば同じ判断で続けられるようにする。
実装の仕組みは各 doc（リンク先）、いまの進み具合は `docs/STATUS.md`、技術的な設計判断は `docs/ARCHITECTURE.md` §7。

- 決定の原本は GitHub Issue のコメント（非公開リポジトリ。`gh issue view <番号> --comments`）。ここはその写しと、決めた理由・実装の場所
- **`owner-decision` の論点は、オーナーの「はい」なしに決めて実装しない**（`AGENTS.md`）。聞くときは選択肢と推奨案を示し、答えを Issue のコメントに残してからここに写す
- 決定を変えるときは、この表を書き換えるのではなく「変更」として日付と理由を足す

## 1. 決まったこと（2026-09-26〜27、オーナーの回答）

### 1.1 農園のスタッフアカウント（#24、2026-09-26）

| 論点 | 決定 |
| --- | --- |
| 権限の種類 | 「出荷担当」（注文・発送・送り状・メッセージ）と「すべて」（＋キャンセル・商品・レビュー返信・ショップと配送の設定）の2つ |
| オーナーだけの操作 | 概要（売上）・精算・振込先口座・Stripe・売上明細CSV・スタッフ管理・インボイス登録番号 |
| アカウント | 今の購入者アカウントに所属を足す（ロールは変えない）。1人1農園 |
| 招待 | オーナーがメールで招待。1農園5人まで（招待中を含む）。リンクは7日有効。お客さまへの返信は農園名で届く |

**理由**: お金と口座はオーナーの責任に限り、日々の出荷だけを任せたい。家族やパートが個人で持っている購入者アカウントをそのまま使えるほうが導入しやすい。
**実装**: `config/farm-staff.ts`（権限表 `canFarm`）、`server/auth/guards.ts`（`requireFarm(cap)` / `assertFarm(cap)`。権限の引数は**必須**で、書き忘れは型エラー）、`services/farm-staff.ts`。
**テスト**: `actions/__tests__/farm-staff.test.ts`、`authorization.test.ts`。
**決めていない既定**: スタッフへのお知らせ（今はオーナーにだけ届く）、生産者側の操作記録（発送の履歴に操作した人を残すだけ）。

### 1.2 配達完了の判定（#25、2026-09-26）

| 論点 | 決定 |
| --- | --- |
| 配送業者との API 契約 | **まだ**。業者に依存しない部分だけ先に作る |
| 契約するとき | 運営がまとめて契約し、費用も運営が持つ（生産者は何もしない） |
| API が無い荷物 | **お届け予定日の翌日**に配達完了。お客さまがマイページで「受け取りました」を押せばその場で完了 |
| 届かなかったとき | 生産者と運営に知らせ、**自動完了を止める**（運営が判断） |

**理由**: 配達完了で精算とレビュー依頼が進むので、発送から固定日数で完了にすると、遅れた荷物が届く前に完了になっていた。
**実装**: `services/shipping/delivery.ts#syncDeliveries`（cron `sync-tracking`）、`services/shipping/tracking.ts#trackingAdapters`（業者のつなぎ込み口。今は空）。つなぐ手順は `docs/SHIPPING.md` §5。
**テスト**: `services/__tests__/delivery-sync.test.ts`。

### 1.3 インボイス（適格請求書、#10、2026-09-26）

| 論点 | 決定 |
| --- | --- |
| 運営の登録 | 登録済み／登録予定。番号は `config/site.ts#company.invoiceRegistrationNumber` に入れる（**今は空**） |
| 税率 | 商品はすべて 8%（食品以外は 10% を選べる）、送料・販売手数料は 10% |
| 生産者の番号 | 任意で登録できるようにする（今は保存だけ） |

**理由**: 事業者のお客さまが仕入税額控除を受けられるように。端数は「税率ごとに1回だけ切り捨て」（税理士の確認が前提）。
**注意**: 売主が「各生産者」のままだと、商品代金の領収書に運営の番号が載るのは食い違う。**売主（§2 の #7）が決まるまで運営の番号は入れない**（`docs/PAYMENTS.md`「インボイス」）。
**テスト**: `lib/__tests__/tax.test.ts`、`services/__tests__/invoice.test.ts`。

### 1.4 二重価格（通常価格の打ち消し表示、#11、2026-09-26）

| 論点 | 決定 |
| --- | --- |
| 何を表示するか | **その価格で販売した記録がある**通常価格だけを打ち消し表示する |
| 条件 | 値下げ前の直近8週間の過半（4週間を超える）をその価格で販売し、最後に販売してから2週間以内に値下げした。値下げが8週間を超えたら表示をやめる |
| 記録がない既存の商品 | **記録がたまるまで隠す**（記録はこの変更から始める） |

**理由**: 景品表示法の二重価格表示。販売実績のない「通常価格」を打ち消し表示すると有利誤認になりうる。数値は価格表示ガイドラインの考え方に合わせた想定で、最終的には専門家に確認する。
**実装**: `lib/compare-price.ts`（判定の純関数）、`services/price-history.ts`、表 `variant_price_periods`、毎日の cron `compare-prices`。数値は `config/catalog.ts#comparePricePolicy` だけで変えられる。`docs/DATA_MODEL.md`「通常価格の打ち消し表示」。
**テスト**: `lib/__tests__/compare-price.test.ts`、`services/__tests__/price-history.test.ts`。

### 1.5 出荷準備中のお客さまのキャンセル（#18、2026-09-26）

| 論点 | 決定 |
| --- | --- |
| 準備中になった後 | **キャンセルの依頼**。生産者が承認すると全額返金、断るとそのまま発送（依頼は出荷単位ごとに1回） |
| 複数の農家の注文 | 準備前の農家の分だけ、お客さまが自分で取り消せる（送料を含めてその農家の分を返金） |
| 猶予 | なし。生産者が「準備を始める」を押した時点で締め切り（生産者の画面にその旨を出す） |
| 文言 | 利用規約 第6条・ご利用ガイド・最終確認画面を決めた内容に合わせる（規約は下書きのまま。専門家の確認が要る） |

**理由**: 収穫・箱詰めを始めた後の取り消しは生産者の損になる。一方で一律に断るとお客さまの事情に応えられないので、生産者が判断できる形にした。
**実装**: `lib/order-cancel.ts`（画面と Action が同じ判定）、`services/cancel-requests.ts`、`refunds.ts#refundOrder` の `onlyStatus`（同時押しの守り）。`docs/PAYMENTS.md`「返金・キャンセル」。
**テスト**: `services/__tests__/cancel-request.test.ts`、`authorization.test.ts`。
**決めていない既定**: 生産者が回答しないまま出荷期限を過ぎたときの扱い（今は期限のリマインドが続くだけ）、スタッフへの依頼のお知らせ。
